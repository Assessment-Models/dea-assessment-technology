# Facilitator Guide — Technology Assessment

How to run a facilitated workshop for the technology domain. Self-assessment mode is also supported (see `self-assessment-guide.md`).

---

## Pre-workshop (1 week before)

- [ ] Confirm participants (8–12 people: CTO, platform engineers, security, finance if cost-related)
- [ ] Send pre-read: link to `instrument.yaml` and 5 dimensions
- [ ] Confirm room and tools
- [ ] Send calendar invite with agenda
- [ ] Prepare score sheets (one per dimension)

---

## Agenda (3 hours)

| Time | Activity | Lead |
|------|----------|------|
| 0:00 | Welcome, agenda | Facilitator |
| 0:10 | Dimension 1 — Stack Fitness (40 min) | Platform Engineering |
| 0:50 | Dimension 2 — Technical Debt (40 min) | Engineering Manager |
| 1:30 | Comfort break | |
| 1:40 | Dimension 3 — Lifecycle (35 min) | Platform Engineering |
| 2:15 | Dimension 4 — Skill Coverage (25 min) | People Manager |
| 2:40 | Dimension 5 — Tooling (20 min) | Platform Engineering |
| 3:00 | Cross-cut + actions (30 min) | All |
| 3:30 | Wrap-up | Facilitator |

---

## Per-dimension script

Use the same 5-step process as other assessments:

1. **Context (3 min)** — explain why this dimension matters
2. **Read questions (5–10 min)** — walk through, allow clarifying questions
3. **Individual scoring (5–10 min)** — private scoring on score sheets
4. **Surface disagreements (10–15 min)** — facilitator drives convergence
5. **Lock scores (5 min)** — sum, compute percentage, mark band

---

## Cross-cut discussion (30 min)

- Where does the ATL lag reality?
- Is technical debt growing or shrinking?
- Where are skill SPoFs hiding?
- Are costs tracked but not optimised?

---

## Post-workshop

Within 5 working days: fill in gap-analysis-template.md and target-state-template.md, publish to sponsor.

---

## Common challenges in technology assessments

- **ATL is aspirational.** The list exists but teams ignore it. Counter: ask for ATL adherence metrics.
- **Debt is "fine."** Engineering teams underestimate debt. Counter: ask for quantified evidence (effort, $, risk).
- **Skill SPoF denial.** "We have backups" but they're also on critical projects. Counter: ask for backup schedule.
- **Tooling overlap.** Multiple observability tools, unclear ownership. Counter: consolidate by function.
